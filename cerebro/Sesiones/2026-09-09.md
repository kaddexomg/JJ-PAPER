# ✅ Cambios Implementados — Sesión 09-09-2026

## 1. 🔧 Servidor Estable y Robusto

### Candado Síncrono Bloqueante (`index.js`)
- El `lockServer.listen()` ahora está envuelto en `await new Promise()` → **bloquea la ejecución** hasta que se confirme el puerto 8786.
- Cualquier error de candado (no solo `EADDRINUSE`) aborta con `process.exit(3)`.
- `uncaughtException` ahora marca `status: 'crashed'` en la BD antes de morir.

### Watchdog Menos Agresivo (`session-manager.js`)
- Intervalo: **90s** (antes 60s).
- Umbral de muerte: **3 minutos** sin señal (antes era implícito ~60s).
- Si la sesión está `isConnected() && wsOpen()` → no se toca aunque no haya mensajes.
- Renueva `lastEventAt` en sesiones conectadas para evitar falsos positivos.

### Heartbeat Honesto (`heartbeat.js`)
- Estado dinámico: `online` si hay sesiones WA sanas, `degraded` si existen pero ninguna está sana.
- Ya no miente con `'online'` estático.

## 2. ✉️ Envío Real de Mensajes WhatsApp

### Validación de Número (`outbox.js`)
- **Antes de enviar**, llama a `session.sock.onWhatsApp(jid)` para verificar que el número tiene WhatsApp activo.
- Si NO tiene → marca `status: 'failed'` con error claro.
- Si la validación falla por timeout → intenta enviar de todos modos.

### Mensajes Sin JID No Bloquean la Cola
- Mensajes sin JID ahora se marcan como `'failed'` inmediatamente.

### Backoff Exponencial en Reintentos
- Primer reintento: espera 30s. Segundo: 60s. Tercero: 90s. Máximo: 3 minutos.

### Acuses de Recibo con Sesión Fallback (`wa-session.js` + `outbox.js`)
- `outbox.js` guarda `sent_by` cuando usa sesión de respaldo.
- `onReceipts()` busca por `owner_id` y luego por `sent_by`.
