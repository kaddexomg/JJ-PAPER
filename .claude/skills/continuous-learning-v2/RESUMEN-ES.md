# continuous-learning-v2

Este skill implementa un sistema de aprendizaje continuo para Claude Code que convierte las sesiones de trabajo en conocimiento reutilizable mediante "instintos": pequeñas unidades de comportamiento aprendido con un puntaje de confianza asociado. La versión 2.1 agrega instintos con alcance por proyecto (project-scoped), de modo que patrones específicos de React quedan en el proyecto React, convenciones de Python quedan en el proyecto Python, y solo los patrones verdaderamente universales (como "siempre validar el input") se comparten globalmente. Esto evita la "contaminación cruzada" entre proyectos que existía en v2.0.

Un instinto es un archivo YAML atómico con: id, trigger (cuándo aplica), confidence (0.3 a 0.9), domain (code-style, testing, git, debugging, workflow, etc.), scope (project o global), y evidencia de las observaciones que lo generaron. Sus propiedades clave: es atómico (un trigger, una acción), ponderado por confianza, etiquetado por dominio y con evidencia respaldatoria.

Funcionamiento (pipeline): hooks de PreToolUse/PostToolUse capturan el 100% de la actividad de la sesión (prompts y uso de herramientas) en un repo git, detectando además el proyecto actual. Esto se guarda en observations.jsonl bajo una carpeta por proyecto (hash de 12 caracteres derivado del git remote, o del path del repo si no hay remote). Un agente "observer" en segundo plano (usa Haiku) lee esas observaciones y detecta patrones: correcciones del usuario, resoluciones de errores, flujos de trabajo repetidos; decide si el instinto resultante debe ser project o global. Los instintos se guardan en instincts/personal/ (por proyecto o globales). Luego, con /evolve, instintos relacionados se agrupan en clusters que pueden evolucionar a skills, commands o agents completos, y con /promote un instinto que aparece en 2+ proyectos con confianza promedio ≥0.8 puede promoverse de project a global.

Detección de proyecto (orden de prioridad): variable de entorno CLAUDE_PROJECT_DIR, luego "git remote get-url origin" (hasheado, portátil entre máquinas), luego "git rev-parse --show-toplevel" como fallback, y si no se detecta nada, todo va a scope global. Los datos se guardan fuera de ~/.claude (en $XDG_DATA_HOME/ecc-homunculus o ~/.local/share/ecc-homunculus, configurable vía CLV2_HOMUNCULUS_DIR) para que el guard de rutas sensibles de Claude Code no bloquee las escrituras del observer en background. Usuarios con datos previos en ~/.claude/homunculus pueden migrar con scripts/migrate-homunculus.sh.

Cuándo se activa/usa: al configurar aprendizaje automático de sesiones de Claude Code, al ajustar umbrales de confianza, al revisar/exportar/importar bibliotecas de instintos, al evolucionar instintos en skills/commands/agents, o al gestionar instintos project-scoped vs globales y su promoción.

Puesta en marcha: si está instalado como plugin, los hooks ya están registrados automáticamente (no hace falta tocar settings.json); si se copió manualmente a ~/.claude/skills hay que agregar bloques PreToolUse/PostToolUse en settings.json apuntando a hooks/observe.sh (y evitar duplicar el hook si ya está el plugin, porque causaría doble ejecución y errores de resolución de ${CLAUDE_PLUGIN_ROOT}). Las carpetas se crean automáticamente al primer uso, o manualmente con mkdir. La configuración del observer en background vive en config.json: observer.enabled (default false), run_interval_minutes (default 5) y min_observations_to_analyze (default 20); otros comportamientos están hardcodeados en instinct-cli.py y observe.sh.

Comandos disponibles: /instinct-status (muestra instintos project+global con su confianza), /evolve (agrupa instintos en skills/commands, sugiere promociones), /instinct-export (exporta instintos filtrables por scope/dominio), /instinct-import <archivo>, /promote [id] (promueve instintos de project a global), /projects (lista proyectos conocidos y su cantidad de instintos). La promoción también puede hacerse por CLI: "python3 instinct-cli.py promote <id>", "promote" sin argumentos para auto-promover todo lo que califique, o "promote --dry-run" para previsualizar sin aplicar cambios.

Guía de scope: patrones de convenciones de lenguaje/framework, estructura de archivos, estilo de código o manejo de errores específico → project; prácticas de seguridad, buenas prácticas generales, preferencias de flujo de herramientas (ej. "grep antes de editar") y prácticas de git → global.

Escala de confianza: 0.3 tentativo (sugerido, no forzado), 0.5 moderado (se aplica cuando es relevante), 0.7 fuerte (auto-aprobado para aplicarse), 0.9 casi certero (comportamiento central). La confianza sube con observación repetida del patrón, cuando el usuario no corrige la sugerencia, o cuando coinciden instintos de otras fuentes; baja cuando el usuario corrige explícitamente, el patrón deja de observarse por mucho tiempo, o aparece evidencia contradictoria.

Diferencia clave frente a v1: v1 dependía de skills para observar, que son probabilísticas (disparan ~50-80% de las veces según el criterio de Claude); v2 usa hooks, que se disparan el 100% de las veces de forma determinística, garantizando que ningún patrón se pierda. v2.1 es totalmente compatible hacia atrás con v2.0 y v1 (los instintos globales existentes se pueden migrar, los skills generados en ~/.claude/skills/learned/ de v1 siguen funcionando, y el stop hook de v1 sigue corriendo alimentando también a v2).

Privacidad: las observaciones permanecen locales en la máquina del usuario, los instintos project-scoped están aislados por proyecto, solo los instintos (patrones) pueden exportarse —nunca las observaciones crudas—, no se comparte código ni contenido de conversaciones, y el usuario controla qué se exporta y promueve.
