# data-scraper-agent

Este skill guía la construcción de un agente de recolección de datos completamente automatizado, potenciado por IA, para cualquier fuente pública: bolsas de trabajo, precios, noticias, repositorios de GitHub, resultados deportivos, listados, etc. El agente corre en un horario programado, enriquece los datos recolectados con un LLM gratuito (Gemini Flash), los guarda en Notion, Google Sheets o Supabase, y mejora con el tiempo aprendiendo del feedback del usuario. Todo el stack propuesto es gratuito: Python, Gemini Flash, GitHub Actions y las capas de almacenamiento mencionadas.

Se activa cuando el usuario quiere scrapear o monitorear un sitio o API pública, pide "un bot que revise...", quiere trackear empleos/precios/noticias/repos/deportes/eventos, busca automatizar recolección de datos sin pagar hosting, o quiere un agente que se vuelva más inteligente según sus decisiones.

El concepto central son tres capas: COLLECT (scraper que corre en horario) → ENRICH (IA que puntúa, resume o clasifica) → STORE (Notion/Sheets/Supabase). El stack recomendado usa requests+BeautifulSoup para scraping estándar, Playwright para sitios con JS, Gemini Flash vía REST (500 req/día, 1M tokens/día gratis) para enriquecimiento, Notion API para almacenamiento con buena UI, GitHub Actions cron para programación, y un archivo JSON de feedback en el repo para el aprendizaje (sin infraestructura extra). Es clave construir una cadena de fallback entre modelos Gemini ante agotamiento de cuota (gemini-2.0-flash-lite → gemini-2.0-flash → gemini-2.5-flash → gemini-flash-lite-latest) y SIEMPRE batchear las llamadas al LLM (ej. 7 llamadas para 33 ítems en lotes de 5) en vez de llamar una vez por ítem, para no pegar contra el rate limit.

El workflow tiene 10 pasos: (1) entender el objetivo preguntando qué fuente, qué campos extraer, dónde guardar, qué tipo de enriquecimiento IA y con qué frecuencia correr; (2) diseñar la estructura de directorios del proyecto (config.yaml, profile/context.md, scraper/ con main.py/filters.py/sources/, ai/ con client.py/pipeline.py/memory.py, storage/, data/feedback.json, .env.example, setup.py, enrich_existing.py, requirements.txt, .github/workflows/scraper.yml); (3) construir el scraper por fuente con un schema normalizado (name, url, date_found como mínimo), con patrones para API REST, HTML scraping (BeautifulSoup) y RSS; (4) construir el cliente Gemini con reintentos, rate limiting y fallback automático de modelos ante códigos 429/404; (5) construir el pipeline de IA que arma prompts por lote, usa el contexto del usuario y sus prioridades, y filtra por score mínimo; (6) construir el sistema de aprendizaje por feedback (ai/memory.py) que guarda ejemplos positivos/negativos en feedback.json y los inyecta como sesgo en los prompts futuros; (7) construir el almacenamiento (ejemplo con Notion): deduplicación por URL antes de insertar, mapeo de campos IA (score, resumen, notas) a propiedades de Notion; (8) orquestar todo en main.py (fetch de todas las fuentes, deduplicación global, enriquecimiento condicional si hay GEMINI_API_KEY, sync final); (9) definir el workflow de GitHub Actions con cron (ej. cada 3 horas), disparo manual, instalación de dependencias, ejecución del agente con secrets como variables de entorno, y commit automático del feedback.json actualizado; (10) plantilla de config.yaml donde el usuario controla filtros por keywords, prioridades para la IA, proveedor de storage, estados que cuentan como feedback positivo/negativo, y parámetros de IA (modelo, score mínimo, rate limit, batch size) sin tocar código.

También documenta patrones comunes de scraping (API REST, HTML, RSS, API paginada, páginas renderizadas con JS vía Playwright), una tabla de anti-patrones a evitar (llamar al LLM por ítem, hardcodear keywords en código en vez de config.yaml, scrapear sin rate limit -riesgo de ban de IP-, guardar secretos en código, no deduplicar, ignorar robots.txt, usar requests en sitios con JS, y maxOutputTokens muy bajo que trunca el JSON), y una referencia de límites de los tiers gratuitos (Gemini Flash Lite 30 RPM/1500 RPD, Gemini 2.0 Flash 15 RPM, Gemini 2.5 Flash 10 RPM/500 RPD, GitHub Actions ilimitado en repos públicos, Notion API ilimitada, Supabase 500MB/2GB transfer, Google Sheets API 300 req/min).

Incluye una plantilla de requirements.txt (requests, beautifulsoup4, lxml, python-dotenv, pyyaml, notion-client, playwright opcional) y un checklist de calidad antes de dar el agente por terminado: config.yaml controla todo lo user-facing, profile/context.md con contexto del usuario, deduplicación por URL, cadena de fallback de 4 modelos Gemini, batch size ≤5, maxOutputTokens ≥2048, .env en .gitignore con .env.example de referencia, setup.py que crea el schema de la DB, enrich_existing.py para rellenar scores en filas viejas, el workflow de GitHub Actions comiteando feedback.json, y un README con setup en menos de 5 minutos. Cierra con ejemplos reales de uso (monitorear Hacker News por noticias de funding, alertar caídas de precios en e-commerce, trackear repos de GitHub con tag 'llm', recolectar listados de empleo en Notion, clasificar sentimiento en menciones de Reddit, papers nuevos de arXiv, resultados deportivos en Sheets, watcher de inmuebles) y aclara que no provee un agente ya armado, sino que siguiendo los pasos 1 a 9 se construye uno propio.
